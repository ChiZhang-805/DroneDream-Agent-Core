核对日期：2026-09-07。本文依据本任务的用户要求、当前工作树、实际模型清单、训练数据和已有飞行证据编写。准备基线与后续实现进度分别记录；代码修改不授予模型使用资格，也不等于重新训练或飞行验收已经完成。

## 产品目标与工作约定

用户输入自然语言任务，查看并确认计划后，系统在实际 PX4/Gazebo 仿真中完成连续的长任务：办公室出发、穿门、走廊、楼梯、室外通行、到取件点悬停、载荷变化、临时改取件或送达地点、返航与降落。每一步必须由同一任务状态和真实遥测连接。

- 云端大模型继续使用用户选定的 Kimi 等供应商，负责意图、全局地图、分阶段计划、工具调用、检查与修订、改址和完成复核。
- 本地专家持续读取传感器与任务状态，输出有符号、有幅度、随环境变化的控制请求。普通导航、精细机动和恢复专家需要实际影响速度、制动和转向。
- 当前控制接口选择归一化前/右/上速度轴与偏航速率轴；车辆适配层转换为 m/s 和 deg/s。加速度和加加速度受物理限制，飞控负责跟踪。模型不能自行发明坐标系或任意电机值。
- 地图、拓扑、粗路线和目标位置仍是必要的规划与进展参考。局部模型根据实时环境决定如何运动；坐标参考不能被包装成模型生成的连续控制。
- 感知、风险、稳定性等专家可以输出特征、否决或缩放，但必须被后续控制消费并留下影响记录，不能只有说明文字。
- 每种实际安装的传感器有对应的数据适配和处理路径；不要求每种传感器各安装一个神经网络。缺少的传感器应明确标记不可用。
- 模型包在本地安装；除 WSL 外整体空间目标在 50 GB 内。图像、日志、地图、下载缓存与模型一起纳入预算。
- 训练和强化学习在离线或仿真开发流程完成。通用包和地图专用包分别保存并绑定资产；飞行期间权重只读。
- GPT-6 用于开发本项目代码。此次开发模型切换不改变产品运行时供应商选择。
- 本阶段先把相互依赖的代码及相应测试代码写完整，再运行静态检查、测试、训练、回放和飞行验收。发现问题后继续修正、验证。
- 不在产品界面或仓库增加内部实验轮次标签。资产以内容哈希识别；对外保留软件公开版本。

## 初始代码推进记录（后续变化见接续章节）

连续控制基础加固已经实施，代码按 [模块边界与维护约定](CONTROL_MODULE_BOUNDARIES.md) 组织：

- 控制意图分别绑定模型输入快照与任务参考；安全命令不得超过模型意图期限。连续模型结果的期限从提交时间约束，不能通过消费结果或反复安全检查无限续期。
- 零偏航指令保持零转速；只有显式航向辅助模式才让渡该轴。Harness 缩放实际作用于前/右/上速度与偏航速率，同时保留制动所需的加速度能力。
- 快照验证规范的角色顺序、宽度、融合数值、掩码、所需传感器、有效性与哈希；飞行状态换源/中断后重建历史，动态目标过期明确阻断控制。
- 安全计算过程中指令过期时撤销模型授权，保持命令与观测哈希一致；恢复限速不能高于原任务速度限制。
- 模型质量规则抽入一个共用模块，训练、ONNX 准入、每个专家以及运行包选择共用。风险类别、运动/非运动召回、四轴正负方向及主动动作误差都有独立门槛。历史资料可以读取，但缺少新证据的连续包不能继续获准飞行。
- 专家微调加入仅来自训练集的基础样本回放，并检查专门能力和基础能力保留。没有重新训练当前正式候选包；单元测试的小型合成权重不是产品模型。
- 执行成功后分类计数模型限幅控制、安全方向覆盖、安全制动、路线派生和航向辅助；不再把所有授权次数解释为模型原始指令的执行次数。
- 补齐控制/传感器/模型准入的跨进程 Schema。修正验收时混淆 100 维传感器编码与 110 维策略输入的问题。

### 已有结果及其局限

- 当前训练集 662 条、验证集 690 条，各来自一个完整教师任务，两个任务彼此独立，但都使用相同参考路线。因此不能证明未见路线或多地图泛化。
- 两侧偏航标签均全部为零；两侧 `risk_target >= 0.5` 的样本均为零。验证集 20 条非运动样本是零速度保持，不等于 20 条危险样本。
- 恢复专家只有 41 条训练和 51 条验证样本，其验证运动授权准确率为 84.31%。数据收据明确没有要求恢复事件身份或恢复后进展证明。
- 离线准入收据显示总体运动授权准确率 96.81%、四轴平均绝对误差约 0.0283，并允许进入仿真开发。它不能弥补上面的类别、控制轴和任务覆盖缺口。
- 收据中的约 8.00 ms 是视觉预处理、视觉编码、导航及顾问各自 P99 的求和。分量分位数之和不是一次完整调用的实测 P99；后续须单独报告实际端到端分布。
- 当前候选的实际仿真失败：315 次模型调用，1,283 个模型授权控制应用计数，228 次授权推进，路线回退推进为零，最后受控降落。计数证明模型参与过，不能单凭总数证明每次执行均保留了模型原始控制。
- 其中一次调用约 105.06 ms，超过该包 20 ms 加 50 ms 调度宽限的阈值；没有触发 2 秒外围调用超时。必须区分这些不同期限。
- 本次读取的飞行收据中最大模型参与间隔约 12.01 秒，当前判定上限为 60 秒。需要结合运动/保持阶段重建有效控制覆盖，不能以这个门通过宣称已经达到 4 Hz 连续控制。
- 路线规划净空与运行局部净空不是同一个量：当前代码将路线净空分配给局部净空、定位余量及跟踪误差。该飞行摘要中的局部值 0.15 m 来自此预算，不能直接当作规划要求被降到 0.15 m，也不能把规划净空当作实际飞行最小净空。

## 代码批次与依赖顺序

1. 完成传感器、特征和控制合同。写清采样时钟、单位、坐标、缺失、各轴权限、有效期限和哈希对象；把桌面与开发启动参数接入同一合同。
2. 完成传感器编码与融合。核对原生 IMU/状态、几何、动态轨迹、视觉、负载输入；保持有界历史和各自的新鲜度，模型只消费可解释的有效特征。
3. 完成本地策略训练和风险路径。覆盖前进、侧移、升降、转向、减速、保持、受限空间及恢复；补危险/安全对照；强化每角色质量门和任务级划分。保留适用的学习权重必须有输入语义一致性证据。
4. 完成 Harness 仲裁和执行。按阶段选择专家、处理异常和载荷；记录每次控制来源；过期、改址和传感器失效撤销旧授权。云端参与全局判断，局部实时链持续承担控制。
5. 完成数据记录、资格评估和 Runtime 包装代码。绑定最终模型、代码、地图和车辆；移除默认启动路径中已废弃的模型/插件入口，保留必要且显式隔离的教师、迁移与恢复工具。
6. 同步写完相应回归测试代码和文档后，再统一执行测试阶段。代码完成不等于权重训练完成，权重导出也不等于飞行成功。

进展判断必须理解制动、后退避障和转向过程。不能仅因控制方向暂时背离目标就否决，也不能让安全控制器持续代飞并把整段进展计给模型。需要用带阶段和事件身份的时间窗口判断任务进展。
