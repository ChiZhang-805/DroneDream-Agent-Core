# 地图与无人机解析

用户选择资产后可以使用“拿下快递”这样的自然语言，不必自行拼写工程提示词。
资产理解负责提供地点用途和机型限制；任务规划、工具求解、实时控制与执行授权仍是不同边界。

## 输入与缓存

- 手动入口：地图及无人机卡片上的无背景解析图标。
- 自动入口：`MissionService.prepare` 在真实编排开始前调用 `interpret_mission_assets`。
- 两个入口共用 `AssetInterpretationService`，读取 Core 选定内容版本的地图图结构或飞机物理契约。
- 源文件必须属于版本清单，字节 SHA-256 必须一致。目前接入的是已认证、已规范化的资产；不把任意未解析的网格文件假装成可理解或可飞资产。
- 地图解释覆盖其所有具名地点对应的节点；飞机解释覆盖物理、传感器及控制约束字段。无具名地点的地图可以记录局限，不强迫模型虚构地点。
- 这是对已有结构化地图和物理契约的语义解析，不是新加一个直接理解任意三维网格的视觉模型。

缓存位于 Core 数据目录的 `asset-interpretations.sqlite3`。索引绑定账户、租户、组织、产品范围、源事实摘要、模型选择、接口、语言及提示词摘要；密钥不写入缓存。
源内容、模型或提示词变化会产生新键；相同键重新校验成功后直接复用，不再调用模型。
缓存损坏作为未命中处理，只有新解析校验成功才替换。显式强制重解析失败保留原成功结果。
并发解析不会重复发起请求；容量不足在付费调用之前拒绝。

## 规划与追问

解析结果通过唯一的 `HarnessInputEnvelope.session_context.asset_understanding` 进入真实意图解析和独立检查。它标为 `advisory-only`，不能改变源文件、绕过认证、生成执行凭据，或把静态地图当成实时障碍、定位、电量和负载观测。

提示词要求优先使用真实地图中功能匹配的地点。同一节点的多个别名不是多个目的地；不同且同样合理的取件位置仍需要追问。派送目的地、负载等缺失信息不能凭空补全。经过有界核对后仍缺少关键内容，返回结构化追问，不生成计划，也不保留旧计划的可确认状态。
前端显示追问为聊天回复；用户补充回答时携带原任务上下文，不把“东门那个”当成新任务。

解析未命中的物理调用与规划共用总调用预算，缓存命中为零次。新增调用同时进入摘要和 Harness 输出计数；云端计费仍由真实模型网关负责，单元测试替身不代表实际云端调用。

## 资产认证修复

认证前的输入包和嵌入认证回执后的输出包可能有不同摘要。前端现在分别校验：任务输入摘要对应回执源摘要，输出摘要对应用户选定版本和运行契约。未绑定的默认选择可以从 Core 的真实完整认证记录恢复；显式固定的内容版本不能被悄悄替换。
地图没有飞控（`autopilot=none`）与飞机使用 PX4 不构成冲突，仿真器及其版本等兼容条件仍必须一致。

## 验证边界

测试覆盖真实历史认证合同的输入/输出摘要区别、绑定恢复、拒绝损坏证据、缓存和身份隔离、调用预算、真实编排中的上下文传递及追问返回。
测试中的模型端口明确为离线替身；这些结果不是 Kimi 的任务完成率，也不是飞行验收。
源码与前端构建通过不表示已安装 EXE 自动更新。正式安装包仍需配套当前控制合同的本地模型包、准入证据与一致的源代码冻结。
