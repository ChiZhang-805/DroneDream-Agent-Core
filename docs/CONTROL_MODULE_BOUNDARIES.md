# 连续控制代码组织与维护约定

本文件约束本轮连续控制实现的目录归属与依赖方向。它不是飞行验收报告，也不表示新的模型权重已经训练或发布。

## 接口与行为规范

`native/render_replica/scene_capture.hpp` 是完整 ECM 采集的唯一实现，固定
最多四个常驻线程按不重叠实体集合读取同一个物理回调；返回之前全部汇合，
包括异常路径。后台发布器仅拥有已捕获的值，不保留 ECM；不能用变化标记
缓存代替完整场景，也不能在复制完之后重标采集时间。

`forward_rgb_binding.py` 统一维护被选图像的原始源、原始像素摘要、实际接收
时刻与传感器质量。提交模型前可以选更新的已编码图像，但不能把新时钟或
质量附到旧图上，也不能修改已发布的几何/控制记录。

`model_harness/model_port.py` 的云端连接替换由一个后台线程统一拥有；最多
一个待处理请求。连接代次在调用准入和返回时核对，旧响应不能更新新会话。
构造失败保持不可用；关闭立即撤销准入，第三方关闭卡住不等于资源已排空。
`dynamic_safety.py` 分别限制指令与预测惯性；已测超速不能通过截断预测值消失。

训练来源统一由 `training/mission_groups.py` 计算地图与空间路线分组；
`training/causal_replay.py` 导出、绑定和核验实际回放及留出数据；
`training/causal_policy.py` 的冻结评估器供 BC 与 PPO 共用。
CLI 不再各自用任务名称或输入文件名猜测独立性，也不在实时采集期间保留大型解码观测图。
路线分组按微米量化后的三维线段覆盖计算，合并同一直线上的重叠/相接区间；
改名、逆行、往返、环路换起点或增加共线点不会制造新的验证路线。
这只消除这些确定的重复，不声称相近或部分重叠路线统计独立，也不是未知地图泛化证明。

- 模型输入快照哈希、任务参考哈希、模型调用 ID 各有唯一语义，禁止互相替代。较新的传感器可以否决旧控制，不能让旧输入重新变年轻。
- 模型偏航零值表示保持零转速。只有显式 `route-heading-assist` 才能交给航向辅助；不能根据数值接近零来推断权限。
- Harness 缩放必须被实际控制消费。连续模式不能只改变旧路径的步长；指令保存 `harness_control_scale`，各轴请求按比例收缩，制动加速度上限不因此缩小。
- 任务、车辆、安全限制取更严格值。恢复阶段也不能提高先前的任务速度上限。
- 快照使用固定的编码器顺序、宽度、数值、掩码、所需角色和内容哈希；反序列化时重算有效性，不能信任调用方填写的 `ready_for_control`。
- 传感器年龄分别计算。动态轨迹过期不得当成“周围没有障碍”；飞行状态换源或中断后重新积累连续历史。
- 模型调度前可再次读取真正已到达的原生飞行状态；深度/动态编码和已发布安全记录保持原内容。不得把刷新采集时钟等同于刷新传感器时钟，也不能跨飞行来源拼接。
- 模型资格按专家、控制轴、危险/安全与运动/非运动类别分别检查。没有对应样本时不是满分；零控制样本不能稀释主动动作的误差，总准确率也不能掩盖“该运动时一直保持”。阈值通过统一函数实施。
- 专家微调只回放训练集，不把验证集加入训练；同时报告专家分布和基础控制保留能力。
- 所有飞控发送成功后才能累计“已应用”。拥有模型授权与保留模型动作是不同指标，安全覆盖必须独立归因。
- 安全层改写速度时保持原生实测航向、显式记录批准的零转速，不沿用路径航向或未完成的模型转向；其输入期限和实际传输同样需要验证。
- 安全悬停的下发速度和偏航均为零；可达制动速度只进入独立预测字段和碰撞预测，不得再当作目标速度或实际执行动作。
- 深度转换检查所有原始像素，按实际图像尺寸保持有界图块密度，保留每块最近径向命中的原像素方向。有效像素比例随射线进入融合与特征质量，不能用射线数量代替整图有效率。传感器改档必须同时检查编码、原始标定及原始时间，不能只缩小渲染画面。
- 帧融合先完成不可变扫描准备，再做来源准入，最后在所属线程提交地图；同帧体素更新一次、命中优先、旧帧拒绝。新的命中撤销历史自由许可，独立单射线接口不作为相机帧的另一条默认路径。
- 深度运动跟踪也采用准备／提交：对应扫描通过融合后才提交历史。预测体积必须包含所有用于该轨迹的观测点，重复点和低质量点不能增加独立证据；原始深度占用不因跟踪过滤而消失。
- 状态编码失败不改变历史；缺失 IMU 或位置误差证据不能冒充测得零。几何、动态及状态编码入口各自重校验，不能以调用方曾经经过传感器桥为前提。静态地图后续修改不能改变已导出的导航快照。
- 位置、姿态、IMU 虽分别未过期，其来源接收时间跨度仍不能超过 50 ms。这个拒绝条件不等于完成了真实曝光/设备时钟同步。
- 离线纠正的连续幅度细调只产生带几何/制动检查的训练标签，不能在飞行执行器中变为另一套控制器，也不替反事实动作签发物理资格。
- 单位写入字段名；边界验证非有限数、时间逆序、期限和对象绑定。避免用 `model_copy(update=...)` 绕过安全合同校验。

## 起飞前连接恢复与实时数据就绪

这两项不得合并成单个“连接成功”布尔值：进程启动、通信建立、遥测速率请求成功、
真实传感器持续更新和允许飞行分别留证。Runtime 启动标志不授予解锁权限。

| 文件职责 | 内容 | 明确不做 |
| --- | --- | --- |
| `preflight_recovery.py` | 总期限、有限尝试、失败清理、退避和取消传播 | 不发飞行命令，不在解锁请求后重连 |
| `runtime/px4_offboard_track_executor.py` | MAVSDK 连接、实际未解锁检查、速率回执校验、单一遥测订阅恢复 | 不用“请求了采样率”代替实际传感器频率 |
| `native_preflight.py` | 累计连续独立观测、原始来源时效与路线不确定性检查 | 不重写来源时间，不扩大有效期来凑通过 |
| `sensor_diagnostics.py` | 固定错误分类、白名单映射、有界诊断 | 不转发原始异常文本或传感器内容 |
| `native_state_stream.py` / `perception_health_channel.py` | 原生状态接入、拒收计数和认证健康传输 | 不回退模拟器真值、不借旧磁盘快照续期 |

部署执行器的连续健康窗口为 1 秒，单份来源仍最多 250 毫秒，任一中断清空窗口。
重新发布健康摘要不能使旧深度变新；深度时间、原生定位时间和身份独立验证。
所有必要条件同时成立后才允许进入原有解锁流程，解锁后进入 Offboard 前再次验证。

连接及必需速率请求的临时错误最多尝试三次，先关闭旧资源再退避；不支持的必需
来源、错误配置、用户停止、清理失败和实际已解锁状态直接终止。已发出的解锁请求
即使丢失回执，也永久禁止该客户端再走起飞前重连。最终资源清理由原拥有者负责。

位置速度及动力学订阅负责恢复数据流，不负责恢复任务运动权限。订阅恢复必须获得
新样本；旧值在故障期间失效。飞行中既有的指令期限、制动与飞控失联保护保持独立。
`native_perception_preflight_diagnostics`、`native_perception_offboard_diagnostics` 和
`native-state-sampler-summary.json` 保留等待、拒收与恢复证据。错误健康摘要同样使用
有界后台写盘，避免异常时磁盘写入进一步阻塞感知恢复。

恢复机制不能解决持续算力不足、坏标定或不兼容硬件；这些条件必须明确拒绝飞行，
不能通过重复启动或放宽阈值假装恢复。

## 本批变化与验证范围

本地实时控制与 Harness 的研究、控制量选择及分阶段验收方案见
[本地实时控制研究](LOCAL_REALTIME_CONTROL_RESEARCH.md)。

- 专家选择与飞行状态独立：脱困不撤销取件/悬停等状态对稳定性专家的需求。
- 所有直接模型端口都要求风险专家；历史候选模式的通用策略回退不提供绕过风险检查的权限。
- 已挂载负载时，载重上限必须明确验证为 `True`；缺失值和文本布尔值不提供运动权限，仿真采集例外也不例外。
- 本地调用预算从输入整理之前开始，到裁决和记录构建之后结束；准备阶段超时不伪造实际模型调用次数。原始感知截止时间仍由外层独立检查。
- `SpawnRelativeOffboardClient.set_model_velocity_ned` 是已经批准的模型/安全速度专用入口。它保留世界 NED 速度及经批准的偏航角，不再被起飞前固定航向覆盖。普通位置/速度和起飞保持入口继续遵守原航向策略。
- 飞控接受时间过期仍写入实际接受证据并触发保护；不得把已发生的迟到发送抹掉，也不得为了回执漂亮改变期限。
- `control_uncertainty.py` 统一规划与运行误差尺度，`native_preflight.py` 用真实定位数据核验路线空间预算；只有收紧后的跟踪容差和未过期原始证据可以进入解锁边界。重复健康发布不能刷新独立定位证据。
- `localization_observations.py` 只负责显式训练采集时的有限原生几何片段；`geometry_alignment_audit.py` 只做离线地图对应及方向可观察性分析。两者没有改写位置、协方差、运动许可或飞控发送的入口；其结果不能冒充合格的定位器。
- `local_map_alignment.py` 是有界条件平移求解的唯一计算入口；`map_surface_geometry.py` 统一解析盒体、封闭圆柱和球面的首个可见表面，未支持的形状直接拒绝。原点与端点一同变化，保持不可观察方向，输出候选而非控制权限。最近盒体表面距离只用于明确命名的离线诊断，不是定位求解回退。固定姿态误差、未知物体和源时钟问题不能通过 `usable_candidate` 掩盖；该字段只表示计算候选符合所声明数值范围。
- `simulation_sensor_frames.py` 在运行前解析 SDF 包含链、验证现用摄像头光学参数/外参；不会修改已安装 Runtime。`localization_truth_capture.py` 仅在显式源码学习采集的独立观察器中记录精确碰撞中心及源/接收时间；`localization_truth_audit.py` 在离线求解之后做独立比较。真值记录不进入实时工作器、训练动作输入或定位融合，精确评价也不授予飞行权限。
- 普通仿真、学习结果通道和深度工作器的独立诊断均通过同一精确 canonical-link 组合计算碰撞中心，原“把 link 原点近似当作中心”及缺 link 时回退静态 wrapper 的分支已移除。工作器启动时验证帧文件大小、摘要、机体和偏移绑定；原生状态仍只来自 PX4，真值诊断不能修正动作输入。
- 启动器在源码目录存在时统一选择配套源码工作器，包含非训练预览；源码训练缺失脚本直接报错。只有完整安装且没有该源码脚本时才使用产品自身捆绑工作器，避免新核心导入旧工作器私有接口。
- `training/gazebo_witness.py` 的物理速度使用发布者仿真纳秒时间差，原始主机时间只负责时效与吞吐上限；重复源帧不续期、源时间倒退不生成标签。`gazebo_adapter.py` 的独立结果速度采用相同时间定义。深度工作器明确命名的 `gazebo_wall_clock_velocity_mps` 仍仅是主机时间诊断量，不作为物理训练速度或飞控速度。

观测有效期的统一计算、模型准入与发布前重验见
[观测自适应有效期](ADAPTIVE_OBSERVATION_VALIDITY.md)。它只收紧已有控制许可；
不生成空闲空间、不清理过期障碍、不将最大加速度当成有保证的制动能力，
也不允许计算完成后的发布时间重启原始观测的有效期。

动态几何校准与产品控制严格分离：`geometry_motion_fixture.py` 定义不含电机的测试架及真实相机标定；`geometry_fixture_capture.py` 有界采集源时间图像和独立位姿；`geometry_fixture_transport.py` 将阻塞请求放到无订阅的独立进程，目标限定为固定测试架；`geometry_motion_audit.py` 只做离线扰动/时序敏感性分析。`run_geometry_motion_fixture.py` 不启动 PX4，所有测试架命令都不是模型动作。`analyze_geometry_motion_fixture.py --allow-incomplete-capture` 只允许分析注明失败的证据，不提升捕获状态、不写原生控制输入或协方差。此接口不是用坐标命令替代产品要求的连续速度/转向控制。

`local_pose_alignment.py` 是明确选择的联合位置／姿态候选入口，与固定姿态的条件平移基线互斥，不在失败时自动回退。地图可见性仍由原有统一几何模块负责；旋转绕输入机体参考点，六维秩与排除未知旋转后的平移秩分别报告。`geometry_alignment_audit.py` 用 `pose_fit` 独立命名输出，`localization_truth_audit.py` 在全部求解后比较位置和姿态，不把真值回写求解输入。新求解器没有网络、状态发布、飞控发送和权限提升入口。

`simulation_graphics_lifetime.py` 只构造新渲染子进程环境及实际库摘要；只有 Gazebo 与渲染副本使用该环境，不更改 PX4、控制器、模型、父进程、系统驱动或 Runtime 安装文件。Windows、非 D3D12 与不存在固定 WSL 库的环境不应用此修复。库保留不是飞行或实时性资格。

`simulation_phase_monitor.py` 仅供独立仿真路线/结果监控读取有界阶段上下文；短暂失败沿用的时效上限为原读取起始时刻起 100 ms。它不发控制、不修改执行器阶段、不提供物理落地证明。`gazebo_adapter.py` 区分 spawn、起飞线段和飞行路线，阶段切换前的积压样本不能算航段进度；碰撞监控不因阶段改变而停用。

执行器的 `ControlInputLeaseUnavailable` 只能表示发到适配器之前的期限拒绝。共用 `_dispatch_motion_or_brake` 将该状态转换为有界、无任务推进的原生制动/悬停，然后重新读当前上下文中的最新指令；继续、慢速、重规划和显式仿真示范共用该边界。实际接受超时及其他发送异常保持原失败路径，不能从失败回执伪造“未发送”。过期报文不产生模型应用回执；制动事件单独留痕。

原生状态接入放在 `src/dronedream_agent_core/native_flight_state.py`（不读文件、不发控制）；`control_feature_contract.py` 统一维护特征含义和时间配置的内容指纹。训练、运行时、导出、模型选择和验收消费同一指纹，禁止按张量长度猜测兼容性。

本批实现控制授权、快照完整性和质量门的基础加固，并编写对应的回归测试。新增代码和测试写完后才开始静态检查与测试运行。

这些修改刻意让缺少各轴/危险样本证据的历史连续控制包失去自动准入资格；历史文件不删除，也不改写成合格。已补原生位置/姿态、独立采样、三维几何、独立动作条件风险、因果控制 BC/PPO 及原子装配；模型权重与实际飞行证据另行绑定。唯一执行账本是 [总体架构计划第十二节](AUTONOMY_ARCHITECTURE_MASTER_PLAN.md)，不从历史测试记录推断当前模型包已通过。
