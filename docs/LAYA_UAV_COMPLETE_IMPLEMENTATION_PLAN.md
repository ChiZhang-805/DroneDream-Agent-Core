# Laya 无人机领域决策：完整实施规范

版本：设计 v1，2026-09-24。性质：待实施方案，不是完工记录。

用户要求：给出一套覆盖数据、微调、控制接入、验收和交付的整体方案；不拆成需要用户逐段确认的小任务。实施时依赖顺序仍然存在，但由同一个自动化工作流衔接。模型达不到标准时如实保留失败，不靠放宽标准、删除困难样本或伪造运行结果交付。

## 交付目标与范围

目标不是让 Laya 单独飞行，而是让它在任务、路线和当前感知之间选择合适的行为，使无人机既能推进任务，又能应对临时遮挡、局部变化和非关键数据缺失。

交付包含：领域数据集及来源清单、可重现 Laya 微调与校准、轻量对照模型、决策适配器、实际执行仲裁、自动测试/完整仿真证据、版本化模型包、EXE 安装包及保留用户数据的升级流程。使用域为 Gazebo/PX4 仿真；不能自动扩展成真实无人机适航或安全认证。

固定产品验收任务：用户用自然语言要求“从办公室取外卖并返回，取餐悬停 10 秒，不扫码，先给计划，确认后运行”。大模型实际调用 API 解析任务与地图，产生可校验路线/航点；本地系统完成起飞、通过室内通道/楼梯/出口、到取餐点、确认载物、返航和安全落地。路线可以因实际障碍局部调整，不允许用硬编码轨迹替代自然语言规划验收。

本方案中样本数、频率、门槛、超参数均为设计起点或明确验收要求，不是已有实测成绩。现有记录：正式 RGB 1,232 张、几何观测 4,911 条、风险组 712 个、标签 114,632 条；外部实验池 866 组 RGB/深度/分割。外部池没有自动增加正式控制或决策训练样本。

## 系统职责与控制权限

| 组件 | 输入和职责 | 不得做的事情 |
| --- | --- | --- |
| 大模型/任务执行器 | 用户任务、机型、预解析地图；生成目标、路线与取餐/返回流程 | 伪造地图地点、载物状态；把路线当定位真值 |
| 感知和连续状态估计 | 相机、深度/距离、IMU/飞控状态；提供局部几何、运动趋势、位姿及质量 | 把空检测解释成环境确定无障碍；把未知变零 |
| Laya 行为决策 | 当前目标、近期状态历史、空间、动态物体、可用能力 | 直接发送电机/姿态/速度命令，修改安全门限或地图事实 |
| 连续局部控制器 | 路线局部目标、实时状态、经过批准的行为；产生平滑控制 | 为等待 Laya 阻塞飞控刷新；把旧观测续期 |
| 独立执行仲裁 | 检查当前可执行性、净空、制动、时效、速度/加速度与控制身份 | 把最高概率当安全证明；把独立接管记成模型输出 |

Laya 负责建议行为；取餐完成、任务完成、是否已落地由独立状态证据确认。严重故障的应急处置保留在飞控/安全执行器，不要求五分类模型学习全部应急控制。

现有 RGB-D ORB/PnP 仅有离线相对运动基线，不能命名为已经完成 SLAM。接入它需补齐相机外参、时间同步、连续状态滤波、地图坐标对齐、失配拒绝与重定位测试。优先扩展现有连续定位模块，避免并列运行多个互相冲突的定位源；不默认引入 GPL 组件或声称全部代码仍为 MIT。定位改造是共享状态提供者，不能在 Laya 内再复制一套定位逻辑。

## 固定行为契约

沿用现有五个稳定行为 ID，并为它们规定执行语义，避免训练/推理/控制三处定义不一致。

| ID | 用户可理解的含义 | 执行语义与退出条件 |
| --- | --- | --- |
| follow_route | 沿当前路线继续 | 控制器跟随局部目标，仍实时避障；目标变化或新风险立即重审 |
| slow_down | 降速通过 | 在机型制动能力及净空允许的速度上限内推进，不固定为任意单一速度 |
| wait | 暂时等待 | 在已验证可保持位置的区域稳定等待；临时障碍消失且条件恢复后继续 |
| replan | 绕行或改局部路线 | 保留原任务，调用局部规划器产生并验证替代路径；不执行未验证路径 |
| request_observation | 补充关键观测 | 请求更新对应传感器/定位；若仍有足够独立运动依据则限速衔接，否则稳定等待或按应急策略处理 |

“补充观测”不是“立即结束任务”。直播中断、日志写入延迟、非必要语义字段缺失不会单独触发停飞。是否能继续取决于当前动作需要的能力，而不是要求全部传感器永远完美。

危险出现时独立安全控制立即响应，不等待决策去抖；正常行为切换采用初始 200 ms 的去抖/滞回，防止反复继续—等待。该时间仅用于非紧急切换，通过验证集调整并冻结。

## 状态数据接口

新增版本化 DecisionStateV2，不直接改变旧 StageState 字段语义。旧回放数据保留原版本；显式转换器遇到无法补出的字段必须保留 unknown。

每条状态包括以下字段组：

- 身份：schema_version、mission_id、route_hash、goal_id、scene_family、vehicle_profile_hash、sensor_calibration_hash、observation_time、sequence。
- 任务：规范化当前子目标、任务状态、与取餐/返回相关的必要限制；不直接把任意用户原文拼进决策系统指令。
- 路线关系：局部目标相对位置、横向/高度偏差、前方转弯、局部路径验证版本；路线是目标，不是定位测量。
- 运动：三轴速度、朝向、角速度、负载类别、制动能力；保留数据来源和采样年龄。
- 空间：前后左右上下的距离/已观测范围、地面/天花板高度带、出口/楼梯过渡状态、局部可行空间是否覆盖候选动作。
- 动态目标：经过跟踪的相对位置、速度、占用当前通道的预测时间范围及可信度。只看见一次的人不能直接声称有可靠速度。
- 不确定性：定位误差范围、几何质量、各关键源的 observed_at 与有效期；字段缺失和字段确认不存在必须区分。
- 历史：最近约 2 秒的压缩状态及已实际执行行为，不用单帧代替运动趋势；事件发生时额外保留原始窗口。
- 能力：当前是否具有维持姿态、速度估计、局部避障、全局定位、保持高度、已验证路线、载物确认等能力；按动作分别检查。

内部地图坐标统一 ENU（东、北、上），需要的机体相对向量统一 FRD（前、右、下），单位米/秒/度；字段名必须带坐标与单位。已有不同坐标合同只在适配边界转换一次，四元数方向和相机光学坐标必须有数值测试。不能靠变量名字相似猜测转换。

Laya 输入是由这份结构化状态生成的固定模板。内部选项 ID 与界面语言无关；界面继续跟随用户对话的中英文。初始上下文上限 1,024 token（最终以固定模型版本实际支持值为准），截断只删除最早的非关键历史；关键状态或选项标记放不下时返回明确无效建议，不静默删掉风险信息。

输出 DecisionAdviceV1 包含：输入摘要、目标/路线版本、五类原始概率、校准概率、推荐行为、产生时间、过期时间、模型版本、是否弃权。安全仲裁结果另行记录，不能篡改成模型原始输出；不要求输出隐藏思维链。

## 一份完整的数据生产与监督规范

### 场景覆盖

数据必须包含正常推进、临时等待、持续堵塞、传感器退化与恢复，不以“失败/未知”占满训练集。

| 场景族 | 必须变化的条件 | 关键学习目标 |
| --- | --- | --- |
| 办公室/走廊 | 宽窄、转角、墙距、照明、速度 | 正常推进、窄处降速，不因外观改变停止 |
| 门口/出口 | 门宽、门状态、门外空间、上下净空 | 通过/等待/改道；先穿过约束再平滑改高度 |
| 楼梯/平台 | 坡度、折返、平台净空、栏杆 | 使用连续空间包络，不逐阶追踪地面起伏 |
| 室外/室内转换 | 路面高差、树冠、车辆、架空障碍 | 连续调整高度，不把 5–8 m 当无条件命令 |
| 行人/移动障碍 | 方向、速度、暂停、遮挡、再次出现 | 区分短时横穿与持续占道，保留任务并恢复 |
| 取餐/返航 | 未载物/已载物、质量变化、悬停点 | 取餐前后状态区别、载物后动态约束 |
| 信息退化 | 非关键直播丢帧、深度短缺、定位漂移、延迟 | 只针对缺失能力降级；恢复后继续 |
| 路线变化 | 旧路线局部堵塞、新障碍、目标切换 | 版本绑定和重规划，不沿旧目标继续发送 |

至少 20 个可复现布局/几何变体来自不同程序化场景族；“只改灯光”不算新布局。跨集合隔离基础布局、其派生变体、轨迹和随机种子，不能同一地图几乎相同画面分到两边。

### 数量与采样

目标首份完整语料为 30,000 个经过校验的决策窗口，而非 30,000 个相邻截图。来自至少 1,000 个任务/扰动片段；数量是工程目标，不承诺达到数量就学会。

基础相机按原生帧率保存必要的事件窗口；决策状态常规抽取 2–5 Hz，关键事件保留前后连续数据，不用重复高频截图凑数量。每个窗口默认约 2 秒历史，可引用原始图像而不重复存储。

训练采样使每个五类行为至少占 10%，单类不超过 50%；达不到则补充相应情境，不能仅复制稀有样本。校准/部署分布测试保留预计实际分布，另有均衡压力测试，两类报告分开。

按场景/任务组建立约 65% 训练、15% 开发验证、10% 校准、10% 锁定测试。校准与自然分布测试不得为凑类别配额改变分布。另建独立、锁定的类别均衡压力集，至少 3,000 个有效窗口、每类至少 300 个；若自然分布测试不足以形成此覆盖，额外采集压力集，不从训练集挪用相邻帧。每份报告注明自身采样分布，不混合加权制造总体成绩。不满足独立组数或类别覆盖就报告数据缺口，不能随机打散图片补齐。

30,000 是首份完整数据产品目标。若学习曲线仍持续改善，可在同一工作流中扩展到 100,000 个经过验证窗口；若错误来自状态缺项、教师标签或接口，不继续堆样本。达到规模/计算预算仍不合格时保留失败模型并报告原因，不无限烧 GPU。

### 标签怎样产生

以独立规划器/控制器提出候选行为，在同一仿真快照和一致外部扰动下分别执行候选，记录最小净空、碰撞/接触、制动距离、任务进展、等待时间、后续恢复与载物状态。

快照必须完整覆盖物理状态、飞控估计器、控制器历史和动态物体；不能只传送无人机位置假装同一初始条件。若无法可靠快照，就用同一种子从头重放，并验证分支时刻状态一致后比较。

短行为至少观察数秒，等待/重规划类要观察至事件结束及恢复，不能因短窗口暂未碰撞就标为正确。所有候选不成立的样本标注为不可决策/应急处理，不硬凑一个最高分。

标签按以下优先级形成：满足物理与任务限制 > 避免碰撞/不可恢复状态 > 保留并推进任务 > 减少无谓等待与绕行。奖励的安全项不能被“更快完成”抵消。数值权重仅在开发集确定并记录版本。

正确行为可以不唯一：保存 acceptable_actions 集合和各候选结果。目标概率仅表达监督中的行为偏好，不冒充真实安全概率；没有可靠分布证据时用明确标签/集合监督，不让标注大模型编 0.93 等数字。

大模型可以整理任务、描述画面、提出候选或检查文本矛盾，但标签必须有仿真结果、可验证几何或审核依据。训练输入只含当时可获得的传感器/估计状态；真值和未来结果只在监督/评价侧。隐藏未来信息决定了“正确答案”但输入无法区分的样本，应标为不确定，不能要求模型猜未来。

人工不是逐帧标注者。自动校验正常处理大部分样本；只有教师冲突、不可观测、载物/任务语义不清等样本进入审核队列。人工审核未完成的记录不进入正式训练。

### 单条记录及存储

记录至少包含：sample_id、schema_version、scene/episode/parent_group、split、vehicle/sensor/map_hash、history_refs、state、candidate_actions、acceptable_actions、label_source、teacher_version、outcome_refs、evidence_hashes、license、quality_flags、formal_training_eligible。

存储用 JSONL/Parquet 管理元数据，图像/视频/深度按相对路径引用；权重用 safetensors。所有集合、标注策略、源文件和预处理版本有清单与摘要。正式验证同时核对文件内容，不能只信文件名、时间戳或旧质量报告。记录 UTC 与单调时间用途，跨进程只传明确同域时间戳，不能混用墙钟和仿真时钟。

## 微调、纠错与选择规则

以固定版本 Laya 英文模型为默认候选，输入为规范化内部状态，而非用户原始语言。多语模型只作为预先定义的对照，不把界面双语需求等同于必须训练全部语言。

默认优化监督分类/偏好分布：先适配决策头，再解冻编码器上部或全体做低学习率适配，均属于同一训练作业的可配置训练日程。不能把未训练的 tiny MLP 权重称为 Laya 微调结果。

起始设置：AdamW，编码器学习率 1e-5、决策头 5e-5，权重衰减 0.01，有效 batch 32，最多 8 epoch，5% warmup，梯度裁剪 1.0；混合精度、梯度累积、编码器与头部 activation checkpointing。实际是否解冻全体由显存/开发集曲线决定，配置和差异必须记录。

有可靠单标签时使用交叉熵，有可靠软标签时使用软交叉熵；有多个合格动作时采用集合监督，避免惩罚另一条安全可行行为。标签冲突不可简单多数表决后当硬真值。

官方 RLCD 训练目标作为预定义对照实验，不默认比监督训练更好。最多比较“监督微调”和“监督微调+RLCD”两类主要方案；在同一开发/校准集与相同数据预算下比较，测试集不参与选择。该 RLCD 离线分布训练不等于无人机已在物理环境学会闭环控制。

必须测试选项顺序变化、无关文字变化、单位转换、边界数值、小幅噪声和缺失模式。选项顺序变化时同步映射目标，不能制造错标签。仅对确实无关的变化约束预测一致性，不能要求“行人进入通道前后”输出相同。

把候选放进隔离仿真收集它自己会到达的状态，由独立教师重新检查并聚合纠正样本，最多 3 轮自动纠错预算。沿用 DAgger 的数据分布纠正思想；实际送入飞控的动作仍受独立约束。校准/测试地图和种子永远不回流训练。

保留规则、现有 tiny-tree/MLP 为对照。若 Laya 质量有效但 CPU 太慢，可在同一已验证真实语料上训练轻量学生；教师建议仅为辅助软标签，不能替代结果证据。压缩/量化后的模型是新候选，必须重测概率、时延和闭环，不能只比较文件变小。

所有训练保存：配置、种子、数据清单、分组划分、优化器/调度器/RNG 状态、可续训 checkpoint、逐类结果、校准参数与最佳候选选择依据。异常恢复不能把旧 optimizer 套在不同模型/数据上。

## 校准与实际决策

校准集不参与训练，也不用锁定测试拟合温度。固定五选项任务拟合独立温度；同时报告 NLL、Brier、ECE 与可靠性分布。删除/迁移继承的按选项数温度覆盖必须显式验证，防止新温度被旧配置掩盖。

可执行动作集合由实时几何/控制状态独立给出。先检查集合，再对合法建议使用经过开发集确定的置信度/差距阈值；屏蔽动作后不能重新归一化制造“100% 自信”。当前代码中的 0.8 / 0.2 是影子示例阈值，不能直接认定为已校准产品门限。

对不确定建议使用有明确条件的控制器处理：可能继续限速、补充观测、等待障碍消失或重规划，而不是统一抛出任务失败。没有足够证据支持任何移动时，不因用户希望继续而伪造净空；按已有飞控能力保持或安全处置，并明确报告受限能力。

## 实时接入与容错

Laya 在独立进程运行，初始行为更新 2 Hz，事件到达可唤醒；请求队列只保留最新状态，迟到/乱序/重复结果拒绝。不得同步阻塞 30–50 Hz 连续控制刷新。

目标机并发感知负载下，初始发布性能目标为 Laya 端到端 p95 ≤200 ms、p99 ≤400 ms，统计包含状态序列化与 IPC。当前测得的原版 CPU 0.5–1.6 秒不能假装已经满足。模型无法达标时评估量化/学生或降低其职责频率；不得以放宽底层观测有效期来迁就模型。

行为建议与运动许可分开：建议有效期初始上限 750 ms，但每个具体控制命令仍由最新观测重新验证。Laya 建议过期不代表实时控制链必然失效；也不代表上一条建议可以无限续用。

现有有界混合控制约束继续保留：仅在其原有适用条件成立时衔接，初始上限 0.25 m/s、单次 1.5 秒、累计位移 0.35 m。它针对连续小模型延迟，不是让 Laya 2 Hz 建议每次都消耗同一接管预算。独立检查真实执行历史、原始观测有效期、目标与路线身份；禁止借间歇模型回复重置额度。

区分并测试：可选媒体缺失、推理超时、模型输出损坏、感知暂时退化、定位不可观测、路线失效、执行器拒绝、用户取消。硬合同错误不能被重新命名为“短时延迟”；可选日志故障不能被误归为“传感器全部失效”。

短时困难保留任务。等待/恢复必须有事件条件、重试预算和退避：障碍长期不消失则请求局部替代路线；无替代路线则稳定等待并说明，而不是无限忙循环或伪造完成。只有确认无法继续、需改变用户任务或安全处置时，才升级为人工需求。

## 验收规范与完成定义

以下门槛是拟定发布准入，不是现有成绩；变更必须记录原因，不能为通过测试临时下调。

### 数据与模型

- 许可、源文件、标签证据、跨集合组泄漏检查全部通过；损坏样本隔离且记录，绝不静默跳过后仍宣称全量有效。
- 独立均衡压力集至少 3,000 个有效决策窗口，每类至少 300；自然分布测试另报。可接受行为集合准确率 ≥0.90；仅在经证据确认具有唯一正确行为的子集上计算标准 macro-F1（≥0.90）和五类 recall（各 ≥0.85），每类有效样本不足 100 时补充独立场景而非强行给模糊样本指定唯一标签。两份报告均保留模糊样本数量、集合准确率和逐类错误，不用总体准确率掩盖稀有行为。
- 校准后 ECE 目标 ≤0.05，NLL/Brier 不劣于未校准；报告置信区间与分箱方法，不把校准概率命名为安全概率。
- 已标注明确禁止移动的压力样本中，最终执行仲裁不接受危险移动；同时公布模型原始危险建议数量，不能用拦截器掩盖模型错误。
- 仅非关键媒体变化的对照样本，不应改变推进/停止决策。输入非法、身份变化、乱序、超期均有完整负向测试。
- 若 Laya 不能在质量/时延上提供可解释收益，不作为默认模型；保留规则/已合格控制器，不强行发布一个更差的新模型。

### 实际仿真

- 固定办公室取餐返回任务至少 20 个独立变体完整执行；使用真实任务 API、计划确认、真实控制及实际载物状态证据。不扫码。
- 独立闭环套件至少 200 次：100 次正常/几何/负载变化，100 次动态障碍/信息退化/恢复场景。完整套件 0 次碰撞，任务完成率目标 ≥95%；失败和无谓停顿均保留。样本有限，不外推成现实绝对零风险。
- 正常固定任务 20/20 完成并确认落地；不是跑起飞/悬停小段后当整程通过。
- 比较相同种子下原系统、微调 Laya、轻量对照的任务完成、净空、超时、无谓等待、路径效率和行为振荡；不允许安全变差换平均速度好看。
- 单独核对模型行为、连续控制、独立衔接、安全保持各自的实际发送和状态后果；指令成功返回不等于实际移动成功。
- 直播与用户界面状态来自实际连接/首帧/任务结果，不使用固定倒计时伪装就绪；直播丢失不单独中止飞行。

### 安装与用户体验

- 测试开发环境与已安装环境、升级旧配置/旧对话、中文/空格用户名、不同安装盘、WSL 路径、离线模型加载及资源缺失。不得写死开发者 Q 盘/用户名。
- 模型包绑定权重、tokenizer、状态/动作版本、校准、机型能力与评估清单；不兼容时给出具体修复入口，不只显示笼统执行失败。
- 更新前备份组件与迁移记录，保留对话、地图、账户和用户数据。只能通过产品 RuntimeManager 更新 Runtime，不能直接改 VHDX。
- 软件名称保持 DroneDream · AGENT；用户对话语言决定标题与回复语言。运行中的说明显示真实处理状态和结果摘要，不伪造模型内部思考。
- EXE/安装包构建与哈希检查完成，安装后的进程版本与模型包版本一致；至少从已安装软件入口验证任务计划与启动链。正式更新渠道发布仍须满足签名/发布权限，不能绕过。

## GPU、费用、隐私和人工边界

默认规划单张 24 GB GPU（例如 RTX 4090）用于首次 Laya 领域训练作业，使用 micro-batch 1–2、累积和 checkpointing 控制显存。这是候选配置，不是未测量的显存保证。官方双 T4 示例不是“必须租两张”的依据。

租用前准备完整代码包、标签、训练/校准/开发集合、离线依赖和恢复脚本。人工确认费用上限与租卡后，先测真实序列长度下的显存及吞吐；显存不足先减 micro-batch/降低无关历史开销，不删除关键状态。仍不满足才报告改大显存卡的必要性，不擅自增租。

训练时长预算按真实优化步数/吞吐加验证与导出测算，不直接沿用上游演示时长。单卡已够时不增卡；多卡只有实测并行收益及费用上限明确才采用。训练不需要从公网访问用户数据库。

云端仅上传任务所需的脱敏数据和代码/模型。API 密钥、聊天数据库、个人配置、用户上传的私密地图默认不上传。SSH 主机指纹要独立核对；不关闭校验绕过登录问题。下载权重、必要配置/校准/摘要/评估报告并校验完整后，及时通知用户停止 GPU，除非另获明确停机权限；不能只下载一份缺少 tokenizer/状态版本的裸权重。

人工作用限定为：明确费用/租 GPU、处理第三方许可或访问授权、审核自动系统无法可靠决定的标签/任务语义、必要的应用登录/关闭窗口，以及最终用户体验验收。不应把程序错误、自动化能做的数据格式转换或正常标注校验交给用户。

一个判断不唯一并非必须问用户；按已定义 acceptable_actions 与任务约束自动处理。若需要改变取餐任务、上传私密资产、扩大费用、采用不同发布许可或缺少必需人工授权，则说明精确阻碍并请求决定。
