# 观测自适应有效期：实现与验收

日期：2026-09-09。接续 [传感器到状态判断复核](SENSOR_JUDGMENT_AUDIT.md)。
本阶段只处理观测时效、模型输入准入和安全出口，不增加新的神经网络或改写模型权重。

## 判定的含义

同一幅画面并非对所有用途同时失效。算法返回：

- `control-eligible`：在截止时间内仍通过这一道时效门；**不等于动作安全或已经获得飞行许可**。
- `context-only`：不能再为该控制请求提供时效许可，但可保留为历史、语义上下文和障碍证据。
- `reject`：时钟、数值、来源或参数矛盾，不应作为可信输入。

任何结果都不会清空地图、删除障碍或把未知区域变成自由空间。独立的几何覆盖、状态质量、模型资格、碰撞预测及飞控执行限制继续生效。失效时发出的确定性制动也不被声称为“已经停住”或“必定无碰撞”。

## 有界计算

实现位于 `src/dronedream_agent_core/observation_validity.py`。
判定函数只处理固定数量的标量，时间与额外空间复杂度均为 **O(1)**；不扫描图片、不搜索路径、不调用模型，也不访问磁盘或网络。
运行时复用已有碰撞预测的余量，并汇总最多 512 个既有运动目标的速度；这一小段适配为 O(K)，K 已受合同上限约束。它不是重新处理原始点云。

### 已检查轨迹的额外时间误差

运行时使用 `checked-trajectory-slack`：

1. 独立安全规划器针对实际准备下发的速度/偏航请求计算预测路径与最小净空，包含当前惯性、加速度、jerk 限制和运动障碍。
2. 从该路径的剩余净空中再保留位置不确定性余量；不使用几何编码器的“最近测距”或“自由延伸距离”冒充整条路径的空闲证明。
3. 用相对运动消耗额外余量的模型解出可用时间：`(v + u) × t + a × t² / 2 ≤ M`。
4. 与原始来源的硬截止时间、模型控制意图的截止时间、转向预算同时取更早值；最后扣除后续处理、调度、传输和响应所需预算。

这里 v 取实测与选中速度中较大的幅度，u 取既有目标速度幅度的最大值，不只取径向接近速度，因此不会把横穿目标误当成完全静止。a 采用当前车辆预测模型的加速度上界；位置余量使用额外的三倍标准差项。

**边界：运行时这些输入包含测量/模型估计，不是经过实机标定的必然上界。三倍标准差也不是绝对保证。此规则是额外收紧权限的工程时效门，不是独立的真实飞行安全证明。** 已有预测的不确定性可能与新增余量重叠，这是有意偏保守的处理，可能增加制动次数，不能把单元测试通过等同于飞行可用率已达标。

### 原始空闲距离必须另有制动依据

`swept-free-distance` 模式要求调用方提供针对当前负载、姿态及环境有效的最低制动减速度 b。没有这个依据返回 `context-only`，绝不把车辆的最大加速度当成最低制动能力。

该模式在反应时间 t 后额外保留：

`(v + a × t)² / (2 × b) + u × (v + a × t) / b`

第二项表示本机制动期间障碍物仍可能接近；不能假设本机停止就意味着障碍物也停止。加上反应期间的位移后仍是一个二次不等式，采用数值稳定的正根直接求解。响应预算必须覆盖未包含在制动下界中的执行器延迟和 jerk 建立过程。

该接口已实现并进行边界测试；**当前车辆资产尚未提供合格的最低制动减速度，所以生产适配没有擅自启用这个原始距离放行模式**。当前生效的是上述已有轨迹检查之后的额外时效否决。

## 实际接入与修复

| 阶段 | 已落实的规则 |
| --- | --- |
| 编码后的来源期限 | 各必需编码保留自己的原始采样时刻；更新飞行状态不能更新旧深度。快速转向进一步缩短期限，缺失/饱和角速度不给期限。10° 是当前保守工程阈值，不是已完成相机运动误差标定的结论。 |
| 连续控制图像入口 | 前向图像必须有已支持的仿真场景采样时钟。主机收到图片的时间不能代替拍摄时间；图片比状态更旧时，图片自己的期限约束整个请求。其来源时刻和期限也进入快照内容哈希。 |
| 同源重复调度 | 固定大小的来源期限锁存器只允许期限收紧；同一来源已失去的预算不能因后续转速下降被重新获得。更早的乱序来源不能重启期限。 |
| 推理之前 | 先验来源与预算，再启动视觉预编码。移除了 worker 中绕过准入检查的提前预编码入口。 |
| 准备与推理之后 | 使用同一次提交锚定的单调时钟，计入准备、排队、编译和推理实际耗时。剩余时间不足 70 ms 调度/传输预算的结果不取得控制资格。已经发生的调用仍保留记录，不因结果过期而抹去调用事实。 |
| 动作安全检查之后 | 对实际待发动作的预测净空进行自适应时间检查；余量不足转为独立制动并保留威胁预测。不同动作的净空由安全预测器分别检查，不用一张图的统一标签替代动作检查。 |
| 发布之前 | 不再以“计算终于完成”为理由重启有效期。保留评估时的原截止时间，再检查是否还够传输；否则不发布这条命令，由执行器的既有失联/过期制动策略接管。 |
| 过期/低置信度目标 | 安全预测不再跳过它们。即使调用方错误传入 `stream_healthy=True`，安全边界也会独立拒绝继续运动；最后已知位置及不确定范围继续影响制动预测。 |

250 ms 硬上限和 70 ms 调度/传输预留沿用统一控制时序合同；自适应规则只会缩短，不会延长。低延迟操作系统并无硬实时保证，因此过载时的拒绝与独立制动路径不可省略。

## 设计依据

- [PX4 Collision Prevention](https://docs.px4.io/v1.16/en/computer_vision/collision_prevention)：感知与速度跟踪延迟需要共同考虑，不能只量转换算法耗时。
- [Dynamic Window Approach](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance)：运动可达性与制动/避障约束共同限制可采用的速度。
- [Formal Verification of Obstacle Avoidance and Navigation of Ground Robots](https://www.cs.cmu.edu/~smitsch/pdf/rss_2013.pdf)：反应延迟、制动下界、障碍运动及误差边界需要显式建模；不能把地面机器人证明直接当成无人机安全证明。
